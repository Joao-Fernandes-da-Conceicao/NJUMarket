# NJUMarket v1.2.x 优化路线图

## 📋 概述

本文档列出了在进入 v1.2.x 版本之前，建议完成的优化工作。这些优化主要针对性能、代码质量、架构改进等方面，旨在提升系统的可维护性、可扩展性和用户体验。

---

## 🎯 优化目标

1. **性能优化**：提升系统响应速度，减少数据库查询
2. **代码质量**：提高代码可读性和可维护性
3. **架构改进**：优化系统架构，提高可扩展性
4. **功能完善**：补全占位功能，完善用户体验
5. **错误处理**：统一错误处理机制，提升系统稳定性

#### 1. Service层鉴权机制推广

**问题描述**：

- `sendMessage`方法已实现完整的鉴权机制（验证当前登录用户、用户ID匹配、账户状态等）
- 但其他Service方法可能缺乏类似的鉴权检查
- 需要在所有关键业务操作中推广此鉴权模式

**影响范围**：

- 系统安全性
- 防止用户冒充他人操作
- 防止已禁用账户执行操作

**优化方案**：

**已实现（sendMessage）**：

```java
// ✅ 鉴权检查：验证当前登录用户
User currentUser = UserHolder.getUser();
if (currentUser == null) {
    return Result.fail("用户未登录");
}

// ✅ 鉴权检查：验证传入的userId与当前登录用户匹配
if (!currentUser.getUserId().equals(userId)) {
    return Result.fail("无权操作：用户ID不匹配");
}

// ✅ 鉴权检查：验证用户状态是否为ACTIVE
if (!"ACTIVE".equals(currentUser.getAccountStatus())) {
    return Result.fail("账户已被禁用");
}
```

**需要推广的方法**：

- `deleteMessage()` - 删除消息
- `deleteConversation()` - 删除对话
- `markConversationAsRead()` - 标记已读
- `getConversationDetail()` - 获取对话详情
- `searchMessages()` - 搜索消息
- 其他涉及用户身份验证的操作

**实现位置**：

- `ContactServiceImpl.java` - 统一添加鉴权检查
- 考虑抽取为公共方法或AOP切面

**预计工作量**：2-3小时

#### 3. 异常处理统一化（已完成）

**实现状态**：✅ 已完成

**问题描述**：

- 异常处理不一致，有些用 `e.printStackTrace()`，有些用 `log.error()`
- 缺少异常上下文信息（用户ID、操作类型等）
- 返回给前端的错误信息不够友好

**已完成工作**：

**增强全局异常处理器**：

- ✅ 增强 `GlobalExceptionHandler`，添加更详细的异常分类
- ✅ 添加请求信息上下文（path、method）
- ✅ 区分不同异常类型并返回友好错误信息：
  - `BusinessException` - 业务异常（warn级别）
  - `IllegalArgumentException` - 参数异常（warn级别）
  - `NullPointerException` - 空指针异常（error级别）
  - `RuntimeException` - 运行时异常（error级别）
  - `Exception` - 其他系统异常（error级别）

**重要说明**：

- ⚠️ `GlobalExceptionHandler` 与 Service层异常处理是**互补关系**，不是覆写关系
- Service层主要机制：所有方法都有try-catch，捕获异常后返回`Result.fail()`
- GlobalExceptionHandler兜底机制：只处理传播到Controller层的未捕获异常
- 作用场景：
  1. Service层忘记catch的异常
  2. Spring框架层面的异常（参数绑定、数据验证等）
  3. Controller层直接抛出的异常

**统一异常日志格式**：

- ✅ 所有Service方法的异常处理都使用 `log.error()` 
- ✅ 包含完整的上下文信息：userId、相关ID、操作类型、错误信息
- ✅ 统一错误返回格式

**实现位置**：

- `GlobalExceptionHandler.java` - 全局异常处理增强（兜底机制）
- `ContactServiceImpl.java` - 所有异常处理已统一（主要机制）

**改进示例**：

**全局异常处理器**：
```java
@ExceptionHandler(BusinessException.class)
public Result handleBusinessException(BusinessException e) {
    String requestInfo = getRequestInfo();
    log.warn("业务异常: {}, request={}", e.getMessage(), requestInfo);
    return Result.fail(e.getMessage());
}

@ExceptionHandler(Exception.class)
public Result handleException(Exception e) {
    String requestInfo = getRequestInfo();
    log.error("系统异常: request={}, error={}, type={}", 
            requestInfo, e.getMessage(), e.getClass().getName(), e);
    return Result.fail("系统错误，请稍后重试");
}
```

#### 6. 强制增量轮询机制优化（v1.1.6 后续优化）

**问题描述**：

- 当前强制轮询的延迟时间固定为500ms，不够灵活
- 不同场景下的延迟需求不同（订单支付可能需要更长时间写入Redis）
- 缺少重试机制和错误降级策略

**影响范围**：

- 新消息中订单/商品卡片的加载可靠性
- 用户体验（卡片加载速度）

**优化方案**：

1. **动态延迟机制**：根据变更类型调整延迟时间
   - 订单支付等操作：800ms
   - 商品上架等操作：500ms
   - 默认：500ms

2. **重试机制**：如果强制轮询未获取到数据，延迟后重试（最多3次）

3. **错误处理和降级**：
   - 添加失败计数和限流机制
   - 连续失败超过阈值时，暂停强制轮询一段时间（退避机制）
   - 实现健康检查，定期检查后端增量轮询接口的可用性

**相关文档**：

- 详细改进建议请参考：[v1.1.6 调试总结与改进建议](./V1.1.6_DEBUG_SUMMARY.md)

#### 7. Profile缓存生命周期管理（v1.1.6 后续优化）

**问题描述**：

- 当前Profile缓存没有过期机制，可能导致数据过时
- 长时间不清理，可能导致内存泄漏
- 用户修改昵称/头像时，缓存未自动更新

**影响范围**：

- 内存使用
- 数据一致性（头像/昵称可能显示过时）

**优化方案**：

1. **LRU缓存机制**：限制缓存大小，淘汰最久未使用的数据
2. **缓存过期时间**：定期清理过期缓存（例如30分钟）
3. **缓存失效监听**：监听用户信息变更事件，清除相关缓存

#### 8. 对话列表排序性能优化（计划在v1.3.x完成）

**问题描述**：

- `ContactServiceImpl.getConversations()` 在内存中排序所有对话
- 用户对话数量多时（1000+），性能下降明显
- 当前使用 `Stream.sorted()` 在内存中排序，O(n log n) 复杂度

**影响范围**：

- 用户端对话列表加载速度
- 服务器内存使用（大量对话时）

**注意**：此优化计划在v1.3.x版本完成，不在1.2.x之前完成。

**优化方案**：

**方案A：数据库层排序（推荐）**

```sql
-- 使用 CASE WHEN 实现动态字段排序
SELECT * FROM conversations
WHERE ((user_id_1 = :userId AND user_1_visibility = true) OR 
       (user_id_2 = :userId AND user_2_visibility = true))
  AND status = 'ACTIVE'
ORDER BY 
  CASE 
    WHEN user_id_1 = :userId THEN user_1_last_message_time
    WHEN user_id_2 = :userId THEN user_2_last_message_time
  END DESC
```

**方案B：混合方案（兼容性更好）**

- 对话数量 < 500：内存排序（当前逻辑）
- 对话数量 >= 500：数据库排序（新增逻辑）
- 添加缓存机制，减少重复排序

**实现位置**：

- `ConversationRepository.java` - 添加新查询方法
- `ContactServiceImpl.java` - 修改 `getConversations()` 方法

**预计工作量**：2-3小时
