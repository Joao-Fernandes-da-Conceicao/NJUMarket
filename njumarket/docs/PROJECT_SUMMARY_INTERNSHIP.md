## 2. 简历可用描述（示例）

> **NJUMarket 二手交易平台（后端主导，自研项目）**  
> - 基于 Spring Cloud 构建用户、商品、订单、消息、AI 等服务，使用 OpenFeign + Nacos 做服务发现与调用熔断。  
> - 设计库存扣减链路：Redis 分布式锁 + 数据库悲观锁 + 条件更新，结合数据库事务确保库存一致。  
> - 接入 Elasticsearch 与 pgvector，统一过滤“库存>0 / 非本人商品”，保证检索结果真实可售。  
> - LangChain4j Function Calling：封装商品语义搜索工具，LLM 负责理解需求、调用工具、生成推荐解释。  
> - 配置 Docker + Zipkin + Logback，支持本地/测试环境快速部署与链路追踪。

可根据岗位偏好微调：如偏 AI，则强调 LangChain4j；偏后端，则突出微服务 / 搜索 / 向量库。

## 3. 面试常见问题 & 回答提示

> **说明**：面试官关注“理解程度”“动手实践”，比“超高并发 QPS”更重要。以下问题按“第一次实习”常见场景准备，回答时用自己的话概括，再结合项目细节举例。

### 3.1 项目整体
1. **为什么做这个项目？**  
   说明动机：校园二手交易痛点、想实践微服务 + AI 搜索、希望自我驱动完成较完整的产品。

2. **系统的核心模块有哪些？**  
   简述用户/商品/订单/消息/AI 服务，彼此通过 OpenFeign 通信，使用 Nacos 做注册发现。

3. **遇到的最大问题是什么？怎么解决的？**  
   - Spring AI 版本不稳定 → 迁移 LangChain4j（更易扩展 Function Calling）  
   - Elasticsearch 反序列化时间字段出错 → 使用 SourceFilter + 仅取 `_id`  
   - 库存扣减一致性 → Redis 锁 + `SELECT ... FOR UPDATE` + `updateStockWithCondition` 多重保护

### 3.2 搜索与 AI
1. **语义搜索是怎么做的？**  
   商品发布/更新时生成向量（pgvector），查询时用 LangChain4j Embedding + SQL 向量相似度，过滤库存/可见性/卖家后返回 ID 列表，再从数据库拼装卡片。

2. **AI Agent 为什么要 Function Calling？**  
   让模型先理解用户需求，必要时调用 `searchCommodities` 工具获取结构化商品，再由模型生成自然语言回复，避免“幻觉”并输出可渲染的卡片数据。

3. **对话摘要/上下文怎么做的？**  
   使用 `MessageWindowChatMemory` 维护近期 15 条消息，超过 20 条时自动把旧消息交给 LLM 总结；同时从向量库检索最相关的历史对话补充上下文。

### 3.3 数据与一致性
1. **库存扣减如何保证一致？**  
   - 订单服务层：Redis 分布式锁 + 再查数据库（悲观锁）→ 校验库存/价格/卖家 → 调用内部接口扣减。  
   - 商品服务层：`updateStockWithCondition` 使用 `stock >= quantity` 条件更新，失败即认为库存不足。  
   - 最终在搜索侧统一过滤 `stock > 0`，避免“并发读”造成的售罄商品。

2. **向量或 ES 索引与数据库如何同步？**  
   商品更新时同步 ES 文档 + 异步更新向量；库存变化不刷新向量，但在搜索阶段统一过滤 `stock > 0` 保证结果正确。

3. **缓存设计？**  
   关键数据如商品详情、热门列表使用 Redis 缓存，写入时删除相关 key；聊天与推荐数据实时性高，直接走数据库/向量库。

### 3.4 AI/LLM 常见问
1. **如何控制成本或超时？**  
   对 LLM 请求设置 30s 超时；流式输出时做异常捕获，Broken Pipe 返回 null；仅在必要时才调用搜索 Tool。

2. **如何处理模型的“幻觉”或错误推荐？**  
   Function Calling 返回真实商品列表，LLM 只能复述已有结果；如果列表为空，提示“没找到”并建议用户换关键词。

3. **为什么选择 LangChain4j 而不是 Spring AI？**  
   版本更稳定、Function Calling 体验更好、生态成熟，适合自定义工具与上下文管理。

## 4. 复盘建议

1. **讲思路而不是背答案**：强调自己如何拆分问题、如何验证方案。
2. **多用“示例”**：说搜索过滤时，可举“发布自己商品后再搜索，确认不会出现”等例子。
3. **诚实表达**：暂未经历超高并发，没有压测数据就不用硬凑，转而强调“保证一致性/体验”的做法。
4. **准备少量 Demo 截图或接口返回**：面试中如遇追问，可快速展示证明项目真实存在。
