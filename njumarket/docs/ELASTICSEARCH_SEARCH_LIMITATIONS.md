# Elasticsearch 商品搜索的局限与设计说明

本文档归纳 ES（Elasticsearch）在商品搜索中的**根本性局限**，以及本项目中采用的应对策略，便于后续维护与扩展时统一认知。

---

## 一、核心问题：分词的机械性

Elasticsearch 的检索基于**机械分词**（如 IK 的 `ik_max_word` / `ik_smart`）：对文本做切词、倒排，再按词元匹配。**它不理解语义**，只做字符串/词元的匹配与打分。

因此会出现：

- **同一概念、不同说法**：文档里写「二合一平板」，用户搜「二合一笔记本」或「笔记本」——若文档未同时包含「笔记本」这个词，ES 不会认为二者是“一类东西”，可能搜不到或排序靠后。
- **品牌/型号与描述错位**：用户搜「Surface」，文档标题/描述只写「二合一平板」「可拆卸键盘」等，没有出现 “Surface” 字样——ES 无法建立关联，用「笔记本」搜 Surface 设备也搜不到。
- **同义不同形**：如「考研数学」「数学考研」「考研 数学」等，取决于分词结果和字段是否都覆盖到，可能出现漏检或结果不稳定。

**归纳**：ES 只认“词是否出现、出现多少、在哪些字段”，不认“是不是同一个意思”。这是 ES 的固有特性，无法通过调参或换分词器从根本上解决。

---

## 二、问题归类总结

| 类型 | 表现 | 示例 |
|------|------|------|
| **语义等价、表述不同** | 文档与查询表达同一概念但用词不同，ES 无法等价 | 文档「二合一平板」↔ 用户搜「二合一笔记本」「笔记本」 |
| **品牌/型号未出现在文档** | 用户按品牌、型号搜，文档只写品类或外观描述 | 搜「Surface」↔ 文档仅「二合一 触屏 可拆卸」 |
| **同义词与俗称** | 说法多样，文档或查询只取其一 | 「电脑」「笔记本」「笔记本电脑」「本子」等 |
| **粒度与泛化** | 用户搜较泛词（如「笔记本」），文档写更具体（如「游戏本」「轻薄本」），依赖分词是否切出公共词 | 若文档未含「笔记本」只含「游戏本」，可能不命中 |

以上都可归结为：**机械分词无法建立“语义等价”关系**，只要文档与查询没有足够的**词元重叠**，ES 就会漏检或排序很差。

---

## 三、本项目的应对策略（不改变 ES 机械分词前提）

在**不改动 ES 分词本质**的前提下，项目采用「ES 粗召回 + 上层智能」的分层设计：

1. **索引阶段：LLM 丰度增强（keywordPayload）**  
   建索引/重建时，通过 AI 单次 Chat 为商品生成更丰富的可检索文本（同义词、场景、俗称等），写入 ES 的 `keywordPayload` 等字段，**扩大词元覆盖面**，减轻“表述不同就搜不到”的问题。详见商品服务与 AI 服务的丰度增强逻辑。

2. **检索阶段：ES 保持粗粒度、按相关度排序**  
   ES 使用 multi_match、OR 型逻辑，默认按 `_score` 排序，只做**宽召回**；不依赖 ES 做“精确语义”，避免过度收紧导致漏检。

3. **结果层：LLM 过滤与确认推荐**  
   - 对 ES 返回结果做**语义层面的过滤**：只保留真正符合用户意图的商品（如要「二合一笔记本」则过滤掉普通笔记本）。  
   - 通过 `confirmRecommendedCommodities` 只把过滤后的商品 ID 作为推荐卡片返回，**避免无关商品卡片**展示给用户。

4. **Agent 回溯（搜索 + 过滤后再回溯）**  
   当**完成一次 ES 搜索并做过 LLM 过滤**后，若仍无合适结果，再由 Agent **改进查询词**（同义词、限定词、品牌/型号等）重新调用搜索，形成「搜索 → 过滤 → 仍不足则改词再搜」的闭环，而不是在 ES 层做语义等价。

这样，**“二合一笔记本”和“二合一平板”是一个东西**、**用“笔记本”搜到 Surface 类设备**等问题，主要依靠**丰度文本中补全多种说法**和**LLM 过滤/改词回溯**来缓解，ES 仍只负责基于词元的召回与排序。

---

## 四、仍存在的局限（设计边界）

- **丰度文本的覆盖度**：依赖 LLM 单次生成，若未补全某些品牌/型号或俗称，对应查询仍可能依赖后续 Agent 改词重搜才能命中。  
- **完全未在文档中出现的表述**：若某说法既未在原始描述也未在丰度文本中出现，ES 无法召回，只能靠 Agent 用其他说法再搜。  
- **性能与成本**：多次搜索 + LLM 过滤/回溯会增加延迟与调用次数，当前通过工具调用次数上限（如 5 次）控制。

以上是**在保留 ES 机械分词、不引入向量/语义检索的前提下**的已知边界；若未来需要更强的“同义/跨表述”能力，可考虑引入向量检索或混合检索，与本文档描述的分层设计配合使用。

## 五、相关代码与配置

- 商品搜索与索引：`njumarket-service-commodity` 的 `CommoditySearchService`、`CommoditySearchDocument`、索引重建与丰度写入逻辑。  
- 丰度生成：AI 服务 `CommodityEnrichmentService`、内部接口与 Feign 调用。  
- 过滤与推荐：AI 服务 `AIAgentService` 系统提示、`SearchCommoditiesTool`、`confirmRecommendedCommodities`。  
- 排序：默认按 `_score`（相关度），外源可指定价格、最新等，见 `CommoditySearchService#resolveSort`。
